# Implementation status

Updated: 2026-09-21

This file records verified implementation state. Planned routes in the specification are not counted as implemented.

## Implemented

- Offline conflict acknowledgements now retain the rejected operation payload together with the conflict in one IndexedDB transaction. Settings exposes original-change review and a local JSON download; older conflicts explicitly report missing payloads. This provides manual recovery evidence, not automated conflict resolution. Offline queue tests cover commit failure, atomic acknowledgement rollback, enqueue ordering and payload retention.
- Rich-note editing now applies the disabled state to the editor itself, restarts the autosave delay on every edit, pauses automatic retries after a save failure, and registers a browser unload warning while changes are unsaved or saving. These safeguards do not provide durable offline storage or guard in-app navigation; those remain separate work.
- React/TypeScript/Vite responsive application shell with Inbox, Today, Calendar, Tasks and Brain routes as in-app workspaces.
- Fastify API bound to loopback by default.
- Revisioned owner preferences now keep locale, timezone, notification channels, focus defaults, personal-data sync policy, profile inference, expanded data egress and sensitive school categories inside a closed declarative schema. Empty patches, invalid locale/timezone values, duplicate choices, executable settings and unknown categories are rejected. Settings exposes each consent separately. A live owner-only status surface reports database size/vault count, sync devices and event bounds, worker enrollment/heartbeats, exact versions and an explicit `not_configured` backup state without returning credentials or pretending missing infrastructure is healthy.
- Vault metadata now has owner-bound list/create/detail/update contracts with validated locale/timezone and optimistic revisions. Vaults created through the remote API are explicitly `host_synced` and remote-authorized; the seeded desktop vault remains `machine_local` and is not silently registered by the remote listing. Ordinary metadata patches cannot change storage or privacy mode. Scoped clients see only their exact authorized vault IDs, and the new root metadata mutation is covered by the finite bearer-scope policy.
- PostgreSQL/pgvector migration for vaults, canonical sources, notes, immutable note revisions, idempotent capture operations, tasks and calendar events.
- Capture transaction saves the original source, canonical note, first revision and idempotency record atomically before any AI work.
- URL capture is an explicit-consent durable job. The fetcher permits only public HTTP(S) on default ports, rejects credentials and private/local/link-local/metadata destinations, validates every DNS result, pins the validated address for the request, revalidates every bounded redirect, forwards no credentials, accepts only bounded text/HTML, strips active markup and preserves both requested and final source URLs. Failures remain safe-coded durable jobs; successful captures queue ordinary note processing without treating fetched instructions as executable policy.
- Owner-authored notes can also be created directly as bounded canonical text or editor documents without fabricating an original capture. Note trash/restore is optimistic-revision fenced, history reads address exact immutable revision IDs, and restoring history creates a new revision plus a new classification job rather than rewriting the selected snapshot. The Brain UI exposes new-note creation, trash with an immediate recoverable undo, and revision restoration.
- Resumable original-file upload now uses bounded 4 MiB numbered parts, exact `Content-Range`, per-part and whole-file SHA-256 verification, idempotent part replay, a 2 GiB API maximum and a closed safe media vocabulary. Finalization assembles into content-addressed immutable storage, deduplicates only inside an authorized vault record, and never uses the owner filename as a path. Cancellation removes only that open upload. Blob reads recheck vault ownership, support one bounded HTTP range, force active/unknown types to download, add `nosniff` plus a sandbox CSP, and permit workers only through an active lease whose input explicitly names the blob ID. Browser capture deliberately supports files up to 64 MB. Windows `file_import` keeps the owner-selected path inside Rust, streams files up to the API's 2 GiB bound through the same scoped resumable contract, and returns only the immutable blob record. Both paths retain a retryable link after finalization, link blobs to the canonical source transactionally and show originals in the note editor. Upload alone never sends a file to a model. The Rust path now compiles on the RTX host; authenticated live upload and interruption recovery remain unverified runtime scenarios.
- Real task creation/completion, local calendar creation/listing and Today aggregation endpoints. Today now prefers an already accepted focus block, otherwise derives one deterministic 24-hour next-action slot from known remaining effort, deadlines, priority, recurrence-expanded busy time and explicit scheduling constraints. It returns the exact duration, start, reason and linked school-material coverage; unknown effort yields no fabricated recommendation.
- Manual calendar events now have optimistic revisions, immutable revision history, trash/restore, bounded RFC-style recurrence expansion, one-occurrence cancellation/override records, deterministic free/busy union and overlap conflicts. A bounded calendar projection supports day, week, workweek, month and agenda views; it keeps canonical busy occurrences separate from exact school/deadline overlays and unresolved-time records, and it exposes stale configured Microsoft/Google sources instead of implying fresh synchronization.
- Private event preparation supports manual items, typed provenance, occurrence scoping, revision-safe status changes and removal. Dismissal/removal records suppression, while packing or completing preparation has an explicit no-effect invariant on the underlying commitment.
- Calendar entities now have revision-fenced canonical-name changes and auditable scoped aliases. Same-kind ambiguity is rejected instead of silently merging identities; alias removal is archival and invalidates any automatic preparation match that records that alias as provenance. Commitments expose source evidence, current event bindings and append-only status history. Fulfilment, cancellation, supersession and correction require explicit owner evidence, never the passage of time; changed/terminal/archived commitments invalidate future bindings, and deterministic retry-safe rematching does not duplicate existing preparation. The Tasks UI exposes explicit fulfil, cancel, rematch and guarded archive actions.
- Entity merging is preview-first and same-kind only. The durable proposal records exact source/target revisions plus affected events and commitments; acceptance repeats those checks under a serializable transaction, redirects links, preserves old canonical names as aliases, archives source identities instead of deleting them, invalidates changed commitment bindings and emits an explicit application receipt. Cross-type or newly changed impact sets fail closed.
- Calendar automation policies now use a closed rule vocabulary for source authority, statement kind, identity/date requirements, encounter mode, action and confirmation behavior. Only owner notes can opt into automatic local-only actions; external calendar actions are structurally review-only. Revision-fenced policy updates report newly enabled rules. Bounded dry runs evaluate exact authorized source IDs into explicit suggested/blocked reason codes in a completed no-write job. Decision history has bounded cursor filtering and exposes policy revision/evidence without hidden reasoning; Undo accepts only recorded reversible manifests and applies revision-checked compensating event-trash, prep-invalidation or commitment-archive commands. Settings exposes rule creation, enable/disable, saving, dry-run evidence and reversible decision controls.
- Worker note classification is persisted with source revision, typed result, model digest, prompt version and applied/not-applied audit state. Owner corrections are durable and can lock the classification; later reprocessing records its result but cannot overwrite that lock. Editing a note queues classification from the new canonical revision rather than re-reading the original capture.
- Applied classification operations persist their exact prior metadata, post-operation organization revision and the identity of every rule-added label. Undo restores only those recorded effects and refuses to run after a content edit, owner correction, label/organization change, classification lock or earlier undo.
- Notes can be explicitly reprocessed through a revision-fenced durable job. Only the named `classify` stage is currently accepted, concurrent duplicates reuse the active job, and existing owner classification/label locks remain authoritative when the result returns.
- Canonical area/project/topic/entity labels support aliases, same-kind parent hierarchies, cycle prevention, pinning, revision-safe mutation and note support counts. Owner note-label assignments are read back before editing and are locked by default against later automated organization.
- System and owner collections use a bounded typed filter AST over classification, label, status and literal text containment. Filter values are bound SQL parameters, label references are vault-validated, system filters are immutable, and the sidebar renders actual collection results.
- Versioned routing rules reuse the finite filter AST, validate every condition/target label inside the vault, provide bounded read-only previews, and apply only to future successful classification results. Rules add unlocked associations and cannot remove or replace owner-locked labels; referenced labels cannot be deleted underneath active collections/rules.
